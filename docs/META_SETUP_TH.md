# คู่มือตั้งค่า Meta App สำหรับ HubChat

> เขียนให้คนที่ไม่เขียนโค้ดทำตามได้ — ทำทีละขั้นตามลำดับ อย่าข้าม
>
> ⚠️ **อ่านก่อนเริ่ม** : หน้าจอของ Meta เปลี่ยนบ่อยมาก (ปีละหลายครั้ง)
> ชื่อเมนูในคู่มือนี้อาจไม่ตรงกับที่คุณเห็นเป๊ะ ๆ
> ถ้าหาเมนูไม่เจอ ให้ดูที่ "เรากำลังจะได้อะไร" ของแต่ละขั้น แล้วมองหาเมนูที่ให้ผลนั้น
> และถ้าติดตรงไหน ให้ถ่ายภาพหน้าจอมาถามได้เลย

---

## สรุปว่าเราต้องได้อะไรบ้าง (4 อย่าง)

เมื่อทำครบทุกขั้น คุณจะได้ค่า 4 ตัวไปใส่ในไฟล์ `.env.local` และหน้าตั้งค่าเพจ :

| ค่า | ได้จากขั้นที่ | เอาไปใส่ที่ไหน |
|---|---|---|
| `META_APP_ID` | 3 | `.env.local` |
| `META_APP_SECRET` | 3 | `.env.local` |
| `META_VERIFY_TOKEN` | 5 | `.env.local` (คุณคิดเองได้เลย) |
| **Page Access Token** | 4 | หน้าเว็บ → ตั้งค่า → จัดการเพจ |

## ขั้นที่ 0 — ของที่ต้องมีอยู่ก่อน

- [ ] เพจ Facebook ที่คุณเป็น **แอดมิน**
- [ ] (ถ้าจะใช้ IG) บัญชี Instagram แบบ **Professional** ที่ผูกกับเพจนั้นแล้ว
- [ ] บัญชี Facebook ส่วนตัวของคุณ (ใช้ล็อกอินเข้าเครื่องมือของ Meta)

> 💡 IG ต้องเป็นบัญชี Professional (Business หรือ Creator) เท่านั้น
> บัญชีส่วนตัวธรรมดารับข้อความผ่าน API ไม่ได้

---

## ขั้นที่ 1 — สร้าง Business Manager

**เรากำลังจะได้อะไร** : "บ้าน" ที่เป็นเจ้าของเพจและ token แทนที่จะผูกกับตัวคุณ

1. ไปที่ https://business.facebook.com
2. สร้างบัญชีธุรกิจใหม่ (ใส่ชื่อร้าน / อีเมล)
3. เข้า **การตั้งค่าธุรกิจ (Business Settings)**
4. เมนูซ้าย → **บัญชี → เพจ** → **เพิ่ม** → **เพิ่มเพจ** → เลือกเพจของคุณ
5. (ถ้าจะใช้ IG) **บัญชี → บัญชี Instagram** → เพิ่มบัญชี IG เข้ามาด้วย

> ⚠️ **สำคัญมาก** — สเปกข้อ 6.6 บอกไว้ว่าต้องใช้ token จาก Business Manager
> ไม่ใช่ token ที่ผูกกับบัญชีส่วนตัว
> เพราะถ้าวันหนึ่งคุณเปลี่ยนรหัส Facebook หรือแอดมินคนนั้นลาออก
> token ที่ผูกกับคนจะตายทันที แล้วระบบจะตอบลูกค้าไม่ได้กลางดึก

---

## ขั้นที่ 2 — สร้างแอปของนักพัฒนา

**เรากำลังจะได้อะไร** : แอปที่ทำหน้าที่เป็น "สะพาน" ระหว่างเพจกับระบบเรา

1. ไปที่ https://developers.facebook.com/apps
2. กด **สร้างแอป**
3. เลือกประเภทที่เกี่ยวกับ **ธุรกิจ (Business)**
4. ตั้งชื่อแอป เช่น `HubChat` แล้วเลือกบัญชีธุรกิจที่สร้างไว้ในขั้นที่ 1
5. ในหน้าแอป → **เพิ่มผลิตภัณฑ์ (Add Product)** → เพิ่ม :
   - **Messenger**
   - **Instagram** (ถ้าจะใช้ IG ด้วย)

---

## ขั้นที่ 3 — เก็บ App ID และ App Secret

**เรากำลังจะได้อะไร** : ค่า 2 ตัวแรกสำหรับ `.env.local`

1. ในหน้าแอป → เมนูซ้าย → **การตั้งค่าแอป → พื้นฐาน (App Settings → Basic)**
2. คัดลอก **App ID**
3. กด **แสดง (Show)** ข้าง **App Secret** แล้วคัดลอก

เปิดไฟล์ `.env.local` ในโปรเจกต์ แล้วใส่ :

```
META_APP_ID=ค่าที่คัดลอกมา
META_APP_SECRET=ค่าที่คัดลอกมา
```

> 🔴 **App Secret คือกุญแจบ้าน** — อย่าส่งให้ใคร อย่าโพสต์ อย่าใส่ในภาพหน้าจอ
> ระบบเราใช้ค่านี้ตรวจว่า webhook ที่ยิงเข้ามาเป็นของ Meta จริงหรือของคนแปลกหน้า
> ถ้าหลุด = ใครก็ปลอมเป็นลูกค้าทักเข้าระบบเราได้

---

## ขั้นที่ 4 — สร้าง Page Access Token (แบบ System User)

**เรากำลังจะได้อะไร** : token ที่ระบบใช้ส่งข้อความในนามเพจ

1. กลับไป https://business.facebook.com → **การตั้งค่าธุรกิจ**
2. เมนูซ้าย → **ผู้ใช้ → ผู้ใช้ระบบ (System Users)** → **เพิ่ม**
   - ตั้งชื่อ เช่น `hubchat-server`
   - บทบาท : **ผู้ดูแลระบบ (Admin)**
3. เลือกผู้ใช้ระบบที่เพิ่งสร้าง → **เพิ่มทรัพย์สิน (Add Assets)**
   - เลือก **เพจ** → เพจของคุณ → เปิดสิทธิ์ **จัดการเพจ / ข้อความ** ให้ครบ
   - (ถ้าใช้ IG) เลือก **บัญชี Instagram** → เปิดสิทธิ์เช่นกัน
4. กด **สร้างโทเค็นใหม่ (Generate New Token)**
   - เลือกแอปที่สร้างไว้ในขั้นที่ 2
   - เลือกสิทธิ์ (permission) ให้ครบตามตารางด้านล่าง
5. **คัดลอก token เก็บไว้ทันที** — Meta จะแสดงให้ดูครั้งเดียวเท่านั้น

### สิทธิ์ที่ต้องติ๊ก (สเปกหัวข้อ 6.6)

| สิทธิ์ | ใช้ทำอะไร |
|---|---|
| `pages_messaging` | ส่ง/รับข้อความในนามเพจ |
| `pages_manage_metadata` | ตั้งค่า webhook ของเพจ |
| `pages_read_engagement` | อ่านข้อมูลเพจและคอมเมนต์ |
| `pages_show_list` | มองเห็นรายชื่อเพจ |
| `instagram_basic` | ข้อมูลพื้นฐานของ IG |
| `instagram_manage_messages` | ส่ง/รับข้อความ IG |
| `business_management` | จัดการทรัพย์สินใน Business Manager |

> 🟡 **สิทธิ์ `Human Agent` ต้องยื่น App Review แยกต่างหาก**
> สเปกบอกว่าให้ยื่นตั้งแต่สัปดาห์แรก เพราะรออนุมัตินาน
> **แต่ยังไม่ต้องรอให้อนุมัติก่อนถึงจะเริ่มใช้ระบบได้** —
> ระบบตั้งค่าเริ่มต้นไว้ว่าช่องทางนี้ **ปิด** อยู่ จนกว่าคุณจะยืนยันว่าได้รับอนุมัติจริง

---

## ขั้นที่ 5 — คิด Verify Token ขึ้นมาเอง

**เรากำลังจะได้อะไร** : รหัสลับที่ใช้ยืนยันว่า URL webhook เป็นของเราจริง

ค่านี้ **คุณตั้งเองได้เลย** ไม่ต้องขอจากใคร ขอแค่เดายากและไม่ซ้ำกับรหัสอื่น

สร้างค่าสุ่มด้วยคำสั่งนี้ใน Terminal :

```bash
openssl rand -hex 24
```

เอาค่าที่ได้ใส่ใน `.env.local` :

```
META_VERIFY_TOKEN=ค่าที่สุ่มได้
```

> ค่าเดียวกันนี้จะต้องกรอกซ้ำในหน้าตั้งค่า webhook ของ Meta ในขั้นที่ 7
> ถ้าสองที่ไม่ตรงกัน Meta จะยืนยัน URL ไม่ผ่าน

---

## ขั้นที่ 6 — ทำให้เว็บของเรามีที่อยู่สาธารณะ

**เรากำลังจะได้อะไร** : URL แบบ `https://...` ที่ Meta ยิงเข้ามาได้

Meta ยิง webhook เข้าเครื่องคุณตรง ๆ ไม่ได้ — `http://localhost:3000` ใช้ไม่ได้
เพราะเป็นที่อยู่ที่มีแค่ในเครื่องคุณเท่านั้น ต้องมีทางเลือกหนึ่งใน 2 ทางนี้ :

### ทาง ก. ทดสอบในเครื่องด้วยอุโมงค์ชั่วคราว (แนะนำสำหรับตอนนี้)

```bash
# ติดตั้งครั้งเดียว (macOS)
brew install cloudflared

# เปิดเว็บไว้ก่อนในอีกหน้าต่าง
npm run dev

# แล้วเปิดอุโมงค์
cloudflared tunnel --url http://localhost:3000
```

จะได้ URL หน้าตาแบบ `https://something-random.trycloudflare.com`
**นั่นคือที่อยู่สาธารณะของคุณ** เอาไปใช้ในขั้นที่ 7

> ⚠️ URL แบบนี้เปลี่ยนทุกครั้งที่ปิดแล้วเปิดใหม่ — ต้องกลับไปแก้ในหน้า Meta ทุกครั้ง
> เหมาะกับช่วงทดสอบเท่านั้น ไม่เหมาะกับใช้งานจริง

### ทาง ข. ขึ้นเซิร์ฟเวอร์จริง (ทำตอนพร้อมเปิดใช้)

อัปโค้ดขึ้น Railway หรือ Render (ตามสเปกหัวข้อ 8 ค่าใช้จ่ายราว ฿170–350/เดือน)
แล้วจะได้ URL ถาวรที่ไม่เปลี่ยน

## ขั้นที่ 7 — ตั้งค่า Webhook

**เรากำลังจะได้อะไร** : Meta เริ่มส่งข้อความของลูกค้าเข้าระบบเรา

1. เปิดเว็บของคุณให้ทำงานอยู่ (ขั้นที่ 6) และใส่ค่าใน `.env.local` ครบแล้ว
2. ในหน้าแอปของ Meta → **Messenger → การตั้งค่า (Settings)** → หมวด **Webhooks**
3. กด **เพิ่ม Callback URL** แล้วกรอก :

   | ช่อง | ค่าที่กรอก |
   |---|---|
   | Callback URL | `https://ที่อยู่ของคุณ/api/webhooks/meta` |
   | Verify Token | ค่า `META_VERIFY_TOKEN` จากขั้นที่ 5 |

4. กด **ยืนยันและบันทึก**
   - ✅ ผ่าน = Meta ยืนยัน URL เรียบร้อย
   - ❌ ไม่ผ่าน = ดูหัวข้อ "แก้ปัญหา" ท้ายไฟล์นี้

5. กด **เพิ่มการติดตาม (Add Subscriptions)** แล้วติ๊ก :

   | ช่อง | ทำไมต้องติ๊ก |
   |---|---|
   | `messages` | ข้อความที่ลูกค้าทักมา — **จำเป็นที่สุด** |
   | `message_echoes` | สำเนาข้อความที่เพจส่งออก — ทำให้เห็นข้อความที่ตอบจาก Business Suite ด้วย |
   | `messaging_postbacks` | ลูกค้ากดปุ่ม (ใช้ในรอบคีย์เวิร์ด) |
   | `messaging_referrals` | บอกว่าลูกค้ามาจากแอดไหน |

6. เลื่อนลงหาหัวข้อ **เพจที่เชื่อมต่อ (Access Tokens / Connected Pages)**
   → กด **เพิ่มหรือลบเพจ** → เลือกเพจของคุณ → **ต้องกดสมัครรับข้อมูล (Subscribe)**

   > 🔴 ขั้นย่อยนี้คนลืมบ่อยที่สุด
   > ถ้าไม่กด "สมัครรับข้อมูล" ให้เพจ Meta จะไม่ส่งอะไรมาเลย ทั้งที่ทุกอย่างดูถูกหมด

7. (ถ้าใช้ IG) ทำแบบเดียวกันในหมวด **Instagram → Webhooks** โดยติ๊ก `messages` ด้วย

---

## ขั้นที่ 8 — เชื่อมเพจในระบบเรา

1. เปิดเว็บของคุณ → เข้าสู่ระบบ → **ตั้งค่า → จัดการเพจ**
2. กด **เชื่อมเพจ** แล้วกรอก :
   - **แพลตฟอร์ม** : Facebook หรือ Instagram
   - **Page ID** : เลขของเพจ (ดูได้จากหน้า Messenger → Settings ในแอป Meta)
   - **ชื่อเพจ** : ชื่อจริงของเพจ
   - **Page Access Token** : ค่าที่ได้จากขั้นที่ 4
3. กด **ทดสอบการเชื่อมต่อ**
   - ✅ ขึ้นว่า *"เชื่อมต่อสำเร็จ — Meta ยืนยันว่านี่คือเพจ ..."* = เรียบร้อย
   - ❌ ไม่ผ่าน = token ผิด / หมดอายุ / เป็นของเพจอื่น

---

## ขั้นที่ 9 — ทดสอบว่าข้อความไหลเข้าจริง 🎉

1. เอามือถือของคุณ (หรือให้เพื่อนช่วย) **ทักเข้าเพจ** ด้วยข้อความสั้น ๆ
2. รอ 2–3 วินาที
3. กลับมาที่ **ตั้งค่า → จัดการเพจ** → กด **ประมวลผลคิว**
   - จะขึ้นข้อความบอกว่าได้ข้อความเข้าใหม่กี่ข้อความ
4. เปิด Supabase → **Table Editor** → ตาราง `messages`
   - ต้องเห็นข้อความของคุณอยู่ในนั้น พร้อมแถวใน `customers` และ `conversations`

**ถ้าเห็นข้อความในตาราง = รอบ 3A สำเร็จสมบูรณ์** ✅

> 💡 ปกติไม่ต้องกด "ประมวลผลคิว" เอง ระบบทำให้อัตโนมัติทันทีหลังรับ webhook
> ปุ่มนี้มีไว้ให้ "เห็นด้วยตา" ตอนตั้งค่าครั้งแรก และไว้เก็บงานค้างตอนเซิร์ฟเวอร์รีสตาร์ต

## แก้ปัญหาที่เจอบ่อย

### ❌ Meta บอกว่า "The URL couldn't be validated"

ไล่เช็คตามลำดับ :

1. เว็บทำงานอยู่จริงไหม — เปิด `https://ที่อยู่ของคุณ/api/health` ในเบราว์เซอร์ ต้องได้ผลตอบกลับ
2. `META_VERIFY_TOKEN` ใน `.env.local` **ตรงเป๊ะ** กับที่กรอกในหน้า Meta ไหม (ระวังช่องว่างท้ายบรรทัด)
3. แก้ `.env.local` แล้ว **ปิด `npm run dev` แล้วเปิดใหม่** หรือยัง — Next.js อ่านค่าตอนสตาร์ตเท่านั้น
4. URL ลงท้ายด้วย `/api/webhooks/meta` ครบไหม
5. อุโมงค์ยังเปิดอยู่ไหม (ถ้าใช้ cloudflared)

### ❌ ยืนยัน URL ผ่านแล้ว แต่ทักเข้าเพจแล้วไม่มีอะไรเข้าระบบ

1. **กด "สมัครรับข้อมูล (Subscribe)" ให้เพจแล้วหรือยัง** (ขั้นที่ 7 ข้อ 6) ← สาเหตุอันดับ 1
2. ติ๊กช่อง `messages` ในรายการติดตามหรือยัง
3. เชื่อมเพจในระบบเราด้วย **Page ID ตัวเดียวกัน** กับเพจที่ทักไปหรือเปล่า
   - ถ้า Page ID ไม่ตรง ระบบจะทิ้งข้อความนั้นและเขียน log ว่า *"ได้รับข้อความจากเพจที่ยังไม่ได้เชื่อมในระบบ"*
4. เพจถูกปิดใช้งานในหน้าจัดการเพจอยู่หรือเปล่า
5. ดูตาราง `webhook_queue` ใน Supabase — ถ้ามีแถวเข้ามาแปลว่า Meta ส่งมาถึงแล้ว ปัญหาอยู่ขั้นประมวลผล

### ❌ ระบบเขียน log ว่า "ลายเซ็นไม่ตรง"

`META_APP_SECRET` ผิด — กลับไปคัดลอกใหม่จากขั้นที่ 3 (ระวังคัดลอกไม่ครบ)

### ❌ ทดสอบการเชื่อมต่อเพจไม่ผ่าน

- token คัดลอกมาไม่ครบ (ยาวมาก ต้องคัดลอกทั้งก้อน)
- token เป็นของเพจอื่น — ระบบจะบอกตรง ๆ ว่า id ไม่ตรงกัน
- ตอนสร้าง token ไม่ได้ให้สิทธิ์เพจนั้นในขั้นที่ 4 ข้อ 3

## เช็คลิสต์สุดท้าย

- [ ] `META_APP_ID` อยู่ใน `.env.local`
- [ ] `META_APP_SECRET` อยู่ใน `.env.local`
- [ ] `META_VERIFY_TOKEN` อยู่ใน `.env.local` และตรงกับที่กรอกใน Meta

- [ ] เชื่อมเพจในหน้า ตั้งค่า → จัดการเพจ แล้ว
- [ ] กด "ทดสอบการเชื่อมต่อ" ผ่าน
- [ ] ทักเข้าเพจแล้วเห็นข้อความในตาราง `messages`
