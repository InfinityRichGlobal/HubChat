# เก็บรูปและสลิปไว้เองอย่างถาวร (D-17)

## ปัญหาที่แก้

รูปที่ลูกค้าส่งมาทาง Messenger มาพร้อม **ลิงก์ชั่วคราวของ Meta** ซึ่งหมดอายุในเวลาไม่นาน
พอหมดอายุแล้ว **เปิดดูย้อนหลังไม่ได้อีกเลย**

เรื่องนี้ไม่ใช่ความสวยงาม — **สลิปโอนเงินคือหลักฐานการชำระเงิน**
ลูกค้าโอนมาแล้วเราเปิดสลิปไม่ได้ = ทะเลาะกันโดยไม่มีใครพิสูจน์ได้
และเป็นความเสียหายที่แก้ทีหลังไม่ได้ เพราะไฟล์หายไปแล้วจริง ๆ

**ทางแก้:** ดาวน์โหลดมาเก็บเองทันทีที่ได้รับ ก่อนลิงก์จะหมดอายุ

---

## ตอนนี้ระบบทำงานยังไง (ถ้ายังไม่ตั้งค่า)

ระบบ **ยังใช้งานได้ปกติทุกอย่าง** — ไม่พัง ไม่มี error

แต่ไฟล์ที่เข้ามาจะถูกจดว่า `skipped` แปลว่า "ช่วงนั้นเรายังไม่ได้เก็บ"
ซึ่งทำให้รู้ย้อนหลังได้ว่าไฟล์ไหนหายเพราะอะไร

> ⚠️ **ก่อนเปิดใช้กับลูกค้าจริง ต้องตั้งค่าให้เสร็จก่อน**
> ทุกวันที่ยังไม่ตั้ง = สลิปที่หายไปแบบกู้คืนไม่ได้

---

## สิ่งที่ต้องมี

| อย่าง | ราคา |
|---|---|
| บัญชี Cloudflare | ฟรี (บัญชีเดียวกับที่ใช้ทำ tunnel ได้) |
| R2 storage | **ฟรี 10 GB/เดือน** — รูปแชทของร้านเล็กใช้ไม่ถึง |

> R2 ไม่คิดค่า egress (ค่าโหลดออก) ซึ่งเป็นจุดที่ S3 แพง
> สำหรับร้านขนาดนี้ ค่าใช้จ่ายจริงน่าจะ **0 บาท** ไปอีกนาน

---

## ขั้นตอน — ทำครั้งเดียวจบ

### 1. สร้างถัง (bucket)

1. เข้า https://dash.cloudflare.com → **R2**
2. กด **Create bucket**
3. ตั้งชื่อ เช่น `hubchat-media`
4. Location เลือก **Automatic** (หรือ APAC ถ้ามีให้เลือก)
5. **อย่าเปิด Public access** — ระบบเสิร์ฟรูปผ่านหน้าเว็บเราเองซึ่งตรวจสิทธิ์ทุกครั้ง

### 2. สร้างกุญแจ

1. หน้า R2 → **Manage R2 API Tokens** → **Create API Token**
2. Permissions เลือก **Object Read & Write**
3. Specify bucket → เลือกถังที่เพิ่งสร้าง
4. กด Create แล้ว **จดค่า 3 อย่างนี้ไว้ทันที** (ปิดหน้าแล้วดูซ้ำไม่ได้):
   - Access Key ID
   - Secret Access Key
   - Account ID (อยู่ในหน้า R2 มุมขวา)

### 3. ใส่ใน `.env.local`

```
R2_ACCOUNT_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
R2_ACCESS_KEY_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
R2_SECRET_ACCESS_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
R2_BUCKET=hubchat-media
```

### 4. รีสตาร์ตแล้วทดสอบ

```bash
npm run dev
```

ให้ลูกค้า (หรือตัวเอง) ส่งรูปเข้ามาทาง Messenger แล้วดูล็อก
ถ้าสำเร็จ รูปในหน้าแชทจะเปิดได้ และเปิดได้ตลอดไปแม้ผ่านไปเป็นเดือน

## ตรวจว่าทำงานจริง

```sql
-- ใน Supabase → SQL Editor
select status, count(*) from media_assets group by status;
```

| status | แปลว่า |
|---|---|
| `stored` | ✅ เก็บได้แล้ว เปิดได้ตลอดไป |
| `skipped` | ยังไม่ได้ตั้งค่า R2 ตอนที่ไฟล์เข้ามา |
| `expired` | 🔴 ลิงก์หมดอายุก่อนเก็บทัน — กู้ไม่ได้ |
| `failed` | เก็บไม่สำเร็จ แต่ยังไม่ถึงกับกู้ไม่ได้ |
| `pending` | กำลังเก็บอยู่ |

## เรื่องที่ควรรู้

**ไฟล์ตั้งชื่อตามลายนิ้วมือของเนื้อไฟล์ (sha256)**
ไฟล์เดิมเป๊ะ ๆ จะได้ชื่อเดิมเสมอ → ส่งซ้ำก็ไม่เปลืองที่

**ถังไม่เปิดสาธารณะ**
ทุกครั้งที่มีคนเปิดรูป ระบบตรวจสิทธิ์รายเพจก่อนเสมอ
แอดมินที่ไม่มีสิทธิ์เห็นเพจไหน จะเปิดสลิปของเพจนั้นไม่ได้

**กุญแจ R2 อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น**
ไม่มีทางหลุดไปที่เบราว์เซอร์ — มีชุดทดสอบสถาปัตยกรรมบังคับไว้

**รูปที่แอดมินส่งออก** ยังเก็บที่ Meta (ผ่าน Attachment Upload API)
ถ้าอยากได้สำเนาของเราเองด้วย เป็นงานเพิ่มเติมที่จดไว้เป็น D-45
