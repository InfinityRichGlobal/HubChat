## งานโค้ดที่แก้และตรวจแล้ว

- [x] Comments: รายการสรุป เปิดรายละเอียดทีละรายการ แยกรอจัดการ/ต้องตรวจสอบ/จัดการแล้ว/ลบแล้ว ค้นหาร่วมเพจและสถานะได้ ยกเลิกคำขอเก่าเมื่อเปลี่ยนตัวกรอง และเตือนก่อนทิ้งร่าง
- [x] กันตอบคอมเมนต์ซ้ำทั้งบอทและแอดมิน: ใช้การจองในฐานข้อมูลร่วมกัน เก็บ fingerprint ของคำตอบ กดซ้ำหรือเปิดหลายแท็บไม่ยิงซ้ำ ผลไม่แน่นอนคงสิทธิ์ไว้ให้ตรวจต้นทาง บันทึกผลล้มเหลวไม่รายงานเป็นสำเร็จ
- [x] คิว webhook แยกเหตุการณ์ใน payload ไม่ replay เหตุการณ์ที่สำเร็จแล้วเมื่ออีกเหตุการณ์ล้มเหลว มี backoff, lease fencing และกู้ worker ที่หยุดใน attempt สุดท้าย
- [x] คีย์ cron อ่าน runtime setting เป็นหลักเหมือนค่าตั้งส่วนอื่น ป้องกันค่าเก่าใน deployment ปิดกั้นงานอัตโนมัติ และคำขอที่ไม่ได้รับอนุญาตไม่เขียน heartbeat
- [x] เชื่อม scheduler จาก Settings บน production โดยใช้คีย์ของ deployment เอง ป้องกันคีย์ local ไม่ตรงกัน ยกเลิก Vercel cron รายวันซ้ำ
- [x] งานเบื้องหลังรองรับ scheduler บน Supabase พร้อม Vault และหน้าดู heartbeat/คิว/ลองใหม่หลังแก้สาเหตุใน Settings
- [x] ลูกค้าและประวัติส่งแบ่งหน้าละ 50 รายการ มีตัวกรอง/ค้นหา/หน้าก่อนและถัดไป ไม่ตัดประวัติที่ 200 รายการ
- [x] Inbox และประวัติข้อความใช้เวลา + ID เป็น cursor อ่านรายการเวลาซ้ำได้ครบ ผล polling ว่างไม่ล้างรายการ และการรีเฟรชไม่ลบประวัติที่โหลดเพิ่มแล้ว
- [x] แก้ความละเอียดเวลาไมโครวินาทีในการเรียง/ทดสอบ และเปรียบเทียบเวลาแจ้งเตือนด้วยเวลาจริงแทนข้อความเขตเวลา
- [x] ลดคำขอค่ารูป avatar จากหนึ่งคำขอต่อคนเป็นคำขอร่วมทั้งหน้า
- [x] Diagnostics นับยอดส่ง 24 ชั่วโมงจริง แสดงผลไม่ทราบแยก และไม่อ้างว่าทั้งระบบพร้อมจากแค่การตรวจการตั้งค่า
- [x] Badge คอมเมนต์ตรงงานที่ต้องจัดการและข้อผิดพลาด ตัดรายการลบ/ของเพจเอง และจำกัดสิทธิ์รายเพจ
- [x] Callback ลบข้อมูลตรวจลายเซ็น เก็บคำขอ/สถานะจริง มีหน้าของเจ้าของสำหรับตรวจตัวตนและขอบเขต ลบข้อมูล/ไฟล์ที่เชื่อมโยงอย่างตรวจสอบผลได้ พร้อม retry และป้องกัน replay ประวัติที่ลบ
- [x] แก้ redirect loop ของ session ที่ถูกยกเลิกขณะต้องเปลี่ยนรหัสผ่าน เพิ่ม CSRF origin check และให้ privacy/terms/offline เข้าถึงได้ถูกต้อง
- [x] เก็บ lint warnings โดยแก้สาเหตุ ไม่ปิดกฎ และถอด schema fallback ที่ซ่อน migration ขาด

## งานภายนอกที่ยังต้องยืนยัน

1. Business Verification ยื่นแล้วและรอตรวจ; App Review ยังไม่ส่ง ต้องคัดสิทธิ์ที่ใช้จริง เตรียมบัญชีตรวจเฉพาะและคลิปจริงตาม META_APP_REVIEW_TH.md ก่อนเผยแพร่แอป
2. หลังสิทธิ์พร้อม: ทดสอบ Facebook และ Instagram จากบัญชีจริง ตาม event → webhook → queue → DB → ตอบเพียงครั้งเดียว พร้อมเวลาและผลบนหน้าลูกค้า ปัจจุบันมีหลักฐาน webhook ตัวอย่างถึงระบบ แต่ยังไม่ยืนยันข้อความจริงจากผู้ใช้ทั่วไปครบวงจร
3. การรับ Telegram/Web Push บนอุปกรณ์จริงต้องให้ผู้รับตรวจว่าถึงและได้รับอนุญาตจากอุปกรณ์แล้ว ผล worker หรือชุดทดสอบไม่แทนหลักฐานปลายทางนี้

ผลผ่านในเอกสารนี้หมายถึงขอบเขตที่มีหลักฐานทดสอบ ไม่ใช่การรับรองว่า Meta หรืออุปกรณ์ภายนอกพร้อมทั้งหมด รายละเอียดทางรับข้อมูลรอบก่อนอยู่ใน [META_DELIVERY_REPAIR_TH.md](META_DELIVERY_REPAIR_TH.md)
