**ยังไม่ผ่านครบทุกกระบวนการใช้งานจริง** ผล unit/ฐานข้อมูล/build ยืนยันเฉพาะสิ่งที่ทดสอบ ไม่ใช่ใบรับรองความพร้อมทั้งระบบ

## รอบนี้: Comments และความชัดเจนของหน้าจอ

- [x] เปลี่ยนรายการคอมเมนต์เป็นสรุปที่อ่านเร็ว กดเปิดรายละเอียด/รูป/ประวัติ/ตอบทีละรายการ
- [x] แยก รอจัดการ / ต้องตรวจสอบ / จัดการแล้ว / ทั้งหมด / ลบแล้ว เริ่มที่รอจัดการ
- [x] รายการที่เคยถูกทำเครื่องหมายว่าเสร็จแต่มีข้อผิดพลาด จะอยู่ในต้องตรวจสอบ
- [x] ค้นหาชื่อหรือข้อความร่วมกับเพจและสถานะได้
- [x] โหลดหน้าถัดไปด้วยเวลาและ id กันวน/ข้ามคอมเมนต์เวลาเดียวกัน รองรับเวลาว่าง และไม่แสดงปุ่มโหลดต่อเมื่อหมดจริง
- [x] ยกเลิกคำขอเก่าเมื่อเปลี่ยนตัวกรอง ป้องกันผลลัพธ์เก่าทับผลใหม่; ไม่ส่งข้อความจากการเปิด/ค้นหา/โหลดรายการ
- [x] แยกอัปเดตจากฐานข้อมูลกับดึงย้อนหลังจาก Meta; ดึงย้อนหลังไม่สั่งบอทตอบ
- [x] เมื่อดูหลายหน้า จะหยุดรีเฟรชอัตโนมัติจนกดกลับไปรายการล่าสุด เพื่อรักษารายการที่เปิดดู
- [x] แสดงข้อผิดพลาดพร้อมลองใหม่ แทนการแสดงรายการว่างเหมือนโหลดสำเร็จ; ระหว่างโหลดตั้งค่าบอทไม่แสดงว่าปิด
- [x] เตือนก่อนทิ้งข้อความร่าง กันกดส่งรัวระหว่างคำขอเดิม และปิดส่งขณะอัปโหลด/รอ AI
- [x] จำกัดข้อความ 1,000 ตัวอักษรและต้องมีข้อความตามข้อกำหนด API; ไม่เสนอแนบภาพตอบสาธารณะ Instagram ที่โค้ดไม่รองรับ; ไม่เสนอ unlike Facebook ที่ปลายทางไม่รองรับ
- [x] หน้าลูกค้า: แยกแถวค้นหากับตัวกรอง เพิ่มป้ายชื่อช่องค้นหา/จำนวนที่แสดง/ข้อจำกัด 200 รายการ
- [x] หน้าออเดอร์: เพิ่มชื่อช่องค้นหาและตัวกรองให้เครื่องมือช่วยอ่านหน้าจอ
- [x] หน้า Dashboard: แก้ข้อความที่เคยสรุปยอดขายเทียบค่าแอดว่าเป็นกำไร และลดศัพท์ตั้งค่าภายในในหน้าผู้ใช้

- [x] หน้า Settings: ยกเลิกข้อความที่อ้างว่าใช้งานสมบูรณ์ 100% จากแค่ผลตรวจการตั้งค่า; ระบุชัดว่าต้องทดสอบรับ–ส่งจริง และไม่รายงานว่าคิวพร้อมเมื่อยังไม่มีประวัติส่ง

## งานที่ต้องทำต่อโดยไม่ต้องรอเอกสาร Meta

| ลำดับ | งาน | เกณฑ์ปิดงาน |
|---|---|---|
| P1 | แก้ Data Deletion callback/status | ปัจจุบันอ่านคอลัมน์ `customers.meta_id` ที่ไม่มีและกลืน DB error; status รับ code ใดก็รายงาน completed ต้องมีรายการคำขอจริง ยืนยันการจับคู่ Meta user id กับ PSID อย่างถูกต้อง บันทึกผลจริง และใช้ public routes ตรง AGENTS.md; ทดสอบกับข้อมูลเฉพาะทดสอบ ห้ามลองลบลูกค้าจริง |
| P1 | กู้คิว/worker ให้ทำงานต่อเนื่อง | ปัจจุบันอาศัย webhook `after()` และ cron วันละครั้ง ต้องทดสอบ process crash, งานนานเกินเวลา, retry/backoff, dead-letter และมีวิธีรัน scheduler/worker ที่ใช้งานได้จริงพร้อม heartbeat |
| P1 | ทดสอบและอุดช่องว่าง manual reply เมื่อ Meta รับแล้วแต่บันทึกผล DB ล้มเหลว | `replyPublic` ยัง log ข้อผิดพลาด `finish_public_reply` แล้วคืนสำเร็จ ต้องรายงานผลตามจริง มีหลักฐานกันส่งซ้ำและทดสอบหลายแท็บ/timeout; UI กันคลิกซ้ำรอบนี้ไม่ทดแทนการกันซ้ำฝั่งเซิร์ฟเวอร์ |
| P1 | ทดสอบงานขายครบวงจรบนข้อมูลแยก | รับเข้า → เลือกห้อง → ตอบ → แนบรูป → บันทึกลูกค้า → สร้าง/แก้ออเดอร์ → สลิป/สถานะจ่าย → แพ็ก → นำเข้าเลขพัสดุ → ตรวจยอด; รวมสิทธิ์ owner/admin/viewer และกรณีล้มเหลว |
| P2 | ลูกค้า/ประวัติการส่งมี pagination และค้นหาต่อได้จริง | ลูกค้าและ send-status ยังจำกัด 200 รายการ ต้องไม่ทำให้ข้อมูลเก่าหายจากการค้นหา และมีสถานะโหลด/ข้อผิดพลาด |
| P2 | ปรับ Inbox, Orders และ Settings ให้สม่ำเสมอ | ทดสอบมือถือ/คีย์บอร์ด ป้ายสถานะอ่านง่าย คำอธิบายข้อผิดพลาดบอกขั้นต่อไป ตัวกรองไม่ซ่อนงานโดยไม่รู้ตัว; ทำตามหลักฐานใช้งาน ไม่ย้ายเมนูโดยเดา |
| P2 | ตรวจการแจ้งเตือนและรายการย้อนหลัง | Telegram/Web Push, badge กับตัวกรองต้องนับตรงกัน, การนำเข้าซ้ำต้องไม่แจ้ง/ตอบซ้ำ |
| P2 | เก็บ lint warnings และทบทวน schema fallback เก่า | ไม่ปิดกฎหรือกลืนข้อผิดพลาด; ระบุ migration ที่ต้องมีให้ชัดก่อนรองรับระบบจริง |

## งานฝั่ง Meta ที่พักไว้ตามคำสั่งผู้ใช้

- รอผู้ใช้เตรียมเอกสารยืนยันธุรกิจ; ไม่ขอให้ login/passkey/กรอกข้อมูลเดิมซ้ำ
- หลังพร้อม: Business Verification / App Review / เผยแพร่แอปตามสิทธิ์ที่ใช้งานจริง
- ทดสอบแชทและคอมเมนต์ Facebook/Instagram จากบัญชีจริงที่มีสิทธิ์เหมาะสม แล้วตาม HTTP → queue → DB → ผลตอบเพียงครั้งเดียว
- มีหลักฐาน Meta Dashboard ส่งตัวอย่างถึง queue แล้ว แต่ยังไม่มีหลักฐานว่าข้อความทดสอบจริงจากผู้ใช้ทั่วไปมาถึง webhook ครบ จึงยังไม่ผ่าน end-to-end

รายละเอียดทางรับแชท/คอมเมนต์และ migration ที่แก้รอบก่อนอยู่ใน [META_DELIVERY_REPAIR_TH.md](META_DELIVERY_REPAIR_TH.md)
