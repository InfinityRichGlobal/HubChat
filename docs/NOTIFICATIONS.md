## 1. ภาพรวม 30 วินาที

ระบบแจ้งเตือนมี **สองช่องทาง** ที่ทำงานคู่กัน :

| ช่องทาง | ใช้ทำอะไร | จุดอ่อน |
| --- | --- | --- |
| **PWA Push** | เด้งบนหน้าจอมือถือ/คอมของแอดมินแต่ละคน | ต้องกดอนุญาตทีละเครื่อง / iPhone ต้องติดตั้งลงหน้าจอโฮมก่อน |
| **Telegram** | ส่งเข้ากลุ่มของร้าน | ไม่เด้งใส่หน้าคน ถ้าปิดเสียงกลุ่มไว้ก็ไม่รู้ |

**เปิดทั้งสองอย่าง** เพราะแต่ละอันพังคนละแบบ
มือถือแบตหมด / ปิดแจ้งเตือน / ถอนแอป → ยังมี Telegram ให้ย้อนดู
Telegram โดนจำกัดอัตราส่ง → ยังมี push ที่เด้งทันที

## 2. เหตุการณ์ที่แจ้ง

| --- | --- | --- |
| ลูกค้าทักใหม่ (ยังไม่มีคนรับ) | ทุกคนที่ดูเพจนั้น | webhook |

## 3. ตั้งค่าครั้งแรก (เจ้าของร้านทำครั้งเดียว)

### 3.1 สร้างกุญแจ VAPID สำหรับ push

```bash
npm run vapid
```

จะได้สามค่า นำไปบันทึกที่ **ตั้งค่า → ระบบ + ความลับ** :

```
VAPID_PUBLIC_KEY=...
VAPID_PRIVATE_KEY=...
VAPID_SUBJECT=mailto:อีเมลจริงของร้าน
```

แล้วเพิ่มอีกบรรทัด (ที่อยู่จริงของแอป ต้องเป็น https) :

```
APP_BASE_URL=https://chat.ร้านคุณ.com
```

มีผลทันทีโดยไม่ต้องรีสตาร์ตเซิร์ฟเวอร์

> 🔴 **ทำครั้งเดียวแล้วเก็บไว้ตลอดไป**
> ถ้าเปลี่ยนกุญแจ เครื่องที่เคยกดอนุญาตไว้จะใช้ไม่ได้ทั้งหมด ทุกคนต้องกดอนุญาตใหม่หมด
>
> 🔴 `VAPID_PRIVATE_KEY` คือความลับ ห้าม commit ห้ามส่งให้ใคร
> ส่วน `VAPID_PUBLIC_KEY` เปิดเผยได้ เบราว์เซอร์ต้องใช้อยู่แล้ว

### 3.2 ตั้งกลุ่ม Telegram

1. ทักหา **@BotFather** ใน Telegram → พิมพ์ `/newbot` → ตั้งชื่อ → ได้ token มา
2. บันทึก `TELEGRAM_BOT_TOKEN` ที่ **ตั้งค่า → ระบบ + ความลับ**
3. สร้างกลุ่มในแอป Telegram → เชิญบอทเข้ากลุ่ม → **พิมพ์อะไรสักคำในกลุ่ม**
4. ไปที่ `ตั้งค่า → แจ้งเตือน` กดปุ่ม **"ค้นหากลุ่ม"** จะได้เลข chat id
5. บันทึก `TELEGRAM_CHAT_ID=-100xxxxxxxxx` ที่หน้าเดิม (ไม่ต้องรีสตาร์ต)
6. กดปุ่ม **"ส่งทดสอบเข้ากลุ่ม"** — ต้องเห็นข้อความในกลุ่มทันที

> ⚠️ chat id ของ **กลุ่ม** เป็นเลข **ติดลบ** เสมอ เช่น `-1001234567890`
> ถ้าเห็นเลขบวก แปลว่านั่นคือแชทส่วนตัวกับบอท ไม่ใช่กลุ่ม

## 4. แอดมินแต่ละคนต้องทำอะไร

ไปที่ **ตั้งค่า → แจ้งเตือน** แล้ว :

1. กด **"เปิดแจ้งเตือนบนเครื่องนี้"** → เบราว์เซอร์จะถามว่าอนุญาตไหม → กดอนุญาต
2. กด **"ส่งทดสอบ"** → ต้องเด้งภายใน 10 วินาที
3. เลือกเรื่องที่อยากรู้ / เพจที่อยากรับ / ช่วงเวลาห้ามรบกวน

> **เครื่องแต่ละเครื่องต้องเปิดแยกกัน** — เปิดบนมือถือแล้วไม่ได้แปลว่าคอมจะเด้งด้วย

### 4.1 iPhone / iPad — ต้องติดตั้งก่อน

Apple **ไม่อนุญาต** ให้เว็บที่เปิดในแท็บ Safari ส่งแจ้งเตือน ต้องติดตั้งเป็นแอปก่อนเท่านั้น

1. เปิดเว็บใน **Safari** (Chrome บน iPhone ใช้ไม่ได้)
2. กดปุ่ม **แชร์** (สี่เหลี่ยมมีลูกศรขึ้น) ที่แถบล่าง
3. เลื่อนลงหา **"เพิ่มไปยังหน้าจอโฮม"** → กด **เพิ่ม**
4. **ปิด Safari แล้วเปิดแอป HubChat จากหน้าจอโฮม**
5. ไปที่ ตั้งค่า → แจ้งเตือน → กด "เปิดแจ้งเตือนบนเครื่องนี้"

> นี่คือข้อจำกัดของ Apple ไม่ใช่บั๊กของระบบ
> หน้าตั้งค่าจะขึ้นกล่องสอนวิธีให้เองเมื่อตรวจพบว่ายังไม่ได้ติดตั้ง

### 4.2 ช่วงเวลาห้ามรบกวน

ค่าเริ่มต้นคือ **22:00 – 08:00** (เวลาไทย)

ในช่วงนี้ :
- **ไม่มีอะไรเด้งบนหน้าจอ**
- **แต่ยังส่งเข้ากลุ่ม Telegram ตามปกติ** เพื่อให้ย้อนดูตอนเช้าได้ว่ามีใครทักมาบ้าง

## 5. ตัวเดินตรวจ (สำคัญ — ถ้าไม่ตั้ง จะขาดแจ้งเตือน 2 อย่าง)

แจ้งเตือน 3 ใน 5 อย่างเกิดจาก webhook ที่ Meta ยิงมาเอง
แต่อีก 2 อย่าง — **"เงียบ 15 นาที"** และ **"ใกล้หมดกรอบ 24 ชม."** —
ไม่มีใครยิงมาบอก เพราะมันคือ *การที่ไม่มีอะไรเกิดขึ้น*

จึงต้องมีคนเดินมาดูเป็นระยะ เลือกทางใดทางหนึ่ง :

### ทางเลือก ก — รันโปรเซสค้างไว้ (เครื่องที่บ้าน / Railway / VPS)

```bash
npm run notify
```

ตรวจทุก 60 วินาที ปรับได้ด้วย `NOTIFY_INTERVAL_MS`

### ทางเลือก ข — ตั้ง cron ยิงเข้ามา (Vercel / แพลตฟอร์มที่รันโปรเซสค้างไม่ได้)

บันทึก `CRON_SECRET` ที่ **ตั้งค่า → ระบบ + ความลับ** :

```
CRON_SECRET=สุ่มมาสักชุด (openssl rand -base64 32)
```

แล้วตั้งให้ยิงทุก 5 นาที :

```
POST https://chat.ร้านคุณ.com/api/notify/flush
Authorization: Bearer <CRON_SECRET>
```

บน Vercel ใส่ใน `vercel.json` :

```json
{ "crons": [{ "path": "/api/notify/flush", "schedule": "*/5 * * * *" }] }
```

> ⚠️ **ห้ามตั้งถี่กว่า 1 นาที** — Telegram จำกัดประมาณ 20 ข้อความ/นาทีต่อกลุ่ม
> ยิงถี่เกินจะโดนปลายทางหน่วง แล้วแจ้งเตือนจะมาช้ากว่าเดิม
>
> 🔴 **ห้ามเปิดที่อยู่นี้ให้ใครก็เรียกได้** ถ้าไม่ตั้ง `CRON_SECRET`
> ที่อยู่นี้จะรับเฉพาะเจ้าของร้านที่ล็อกอินอยู่เท่านั้น (เป็นค่าปลอดภัยโดยปริยาย)

## 6. ทำไมยังไม่เด้ง — ไล่ทีละชั้น

ไล่จากบนลงล่าง หยุดที่ข้อแรกที่ยังไม่ผ่าน :

| # | ตรวจอะไร | ดูได้จากไหน |
| --- | --- | --- |
| 1 | เซิร์ฟเวอร์ตั้งกุญแจ VAPID แล้วหรือยัง | หน้าตั้งค่าจะขึ้นกล่องแดงถ้ายัง |
| 2 | เปิดผ่าน **https** หรือ localhost ไหม | http ธรรมดาใช้ไม่ได้เลย |
| 3 | iPhone — ติดตั้งลงหน้าจอโฮมแล้วหรือยัง | ป้าย "ติดตั้งเป็นแอปแล้ว" ในหน้าตั้งค่า |
| 4 | เครื่องนี้กดอนุญาตแล้วหรือยัง | ป้าย "เปิดอยู่บนเครื่องนี้" |
| 5 | กด "ส่งทดสอบ" แล้วมาไหม | ถ้าไม่มา = เครื่องนี้มีปัญหา ไม่ใช่ระบบ |
| 6 | ตัวเดินตรวจทำงานอยู่ไหม | ขาดข้อนี้ = ได้แค่ 3 ใน 5 เหตุการณ์ |
| 7 | เรื่องนั้นถูกปิดไว้เองหรือเปล่า | รายการ "เรื่องที่อยากให้เตือน" |
| 8 | อยู่ในช่วงห้ามรบกวนหรือเปล่า | push เงียบ แต่ Telegram ยังมา |

**เคยกด "ไม่อนุญาต" ไปแล้ว** → ปุ่มในแอปขอซ้ำไม่ได้อีก
ต้องไปเปิดเองใน ตั้งค่าเบราว์เซอร์ → การแจ้งเตือน → หาเว็บนี้ → อนุญาต

## 7. เรื่องที่ระบบทำให้เองอยู่แล้ว (ไม่ต้องกังวล)

- **แจ้งซ้ำ** — ฐานข้อมูลมี unique index บนกุญแจกันซ้ำ
  เหตุการณ์เดียว คนเดียว ช่องทางเดียว = แจ้งได้ครั้งเดียวตลอดกาล
  ตัวเดินตรวจจะวนกี่รอบก็ไม่แจ้งซ้ำ
- **Telegram รวบส่ง** — 20 เหตุการณ์ในรอบเดียวจะรวมเป็น **ข้อความเดียว** ไม่ใช่ 20 ข้อความ
- **เครื่องที่ถอนแอปไปแล้ว** — ปลายทางตอบ 404/410 ระบบจะปิดเครื่องนั้นให้เอง
  ไม่ยิงต่อไปเรื่อย ๆ จนโดนปลายทางแบนทั้งเซิร์ฟเวอร์
- **แจ้งเตือนพัง** — ไม่ทำให้ข้อความของลูกค้าหาย ทุกจุดห่อ try/catch ไว้แล้ว

## 8. ที่อยู่ API ทั้งหมด (สำหรับคนที่ต้องแก้โค้ด)

| ที่อยู่ | วิธี | ใครเรียกได้ |
| --- | --- | --- |
| `/api/notify/subscribe` | GET | แอดมินที่ล็อกอิน — ขอกุญแจสาธารณะ |
| `/api/notify/subscribe` | POST / DELETE | แอดมินที่ล็อกอิน — เพิ่ม/ลบเครื่องของตัวเอง |
| `/api/notify/prefs` | GET / PUT | แอดมินที่ล็อกอิน — ค่าตั้งของตัวเองเท่านั้น |
| `/api/notify/test` | POST | แอดมินที่ล็อกอิน — ยิงเข้าเครื่องตัวเองเท่านั้น |
| `/api/notify/telegram` | GET / POST | เจ้าของร้าน |
| `/api/notify/flush` | POST | cron (Bearer `CRON_SECRET`) หรือเจ้าของร้าน |
